BETRIEBSMODELL / 04

Die Schutzgrenze bleibt.
Der Betriebsort kann variieren.

Die Produktidee ist darauf ausgerichtet, Psoydo innerhalb einer vom Unternehmen kontrollierten Umgebung zu betreiben. Die konkrete Betriebsform zum Launch wird erst mit der technischen Produktdokumentation verbindlich festgelegt.

ZIELBILD / A

Local

Verarbeitung direkt auf einem kontrollierten Endgerät oder innerhalb einer lokalen Umgebung.

STATUS: ARCHITEKTURZIEL · KEINE LAUNCH-ZUSAGE
ZIELBILD / B

On-Prem

Zentraler Betrieb innerhalb der eigenen Infrastruktur des Unternehmens.

STATUS: ARCHITEKTURZIEL · KEINE LAUNCH-ZUSAGE
ZIELBILD / C

Private Cloud

Kontrollierter Cloud-Betrieb innerhalb einer klar abgegrenzten Umgebung.

STATUS: ARCHITEKTURZIEL · KEINE LAUNCH-ZUSAGE

Welche Betriebsformen tatsächlich unterstützt werden, welche Komponenten wo ausgeführt werden und wie Schlüssel, Mapping und Logging technisch umgesetzt sind, wird in der finalen Produktdokumentation verbindlich beschrieben.

MODELLFREIHEIT / 05

Das Modell ist austauschbar.
Die Schutzlogik bleibt davor.

Psoydo ist als modellunabhängige Schutzschicht gedacht. So kann das Unternehmen das Zielmodell nach Eignung für die Aufgabe auswählen, ohne die Schutzlogik an einen einzelnen KI-Anbieter zu koppeln.
